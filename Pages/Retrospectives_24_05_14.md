# 회고_V1

## V1는?

### 목표
- Cropout 샘플 프로젝트를 블루프린트를 이용하지 않고 C++로만 개발해보기
- Unreal Engine의 Game Framework에 대한 이해
- Unreal Engine으로 게임을 개발하는데 필요한 기능 학습
    - 다양한 코드 스니펫 확보
- Data기반의 게임 개발 기술 테스트
- S/W 구조화
    - Application LifeCycle
    - 간단한 Rx
    - 단위 기능의 Manager화

### 고려하지 않은 점
- Cropout 샘플 프로젝트와 100% 동일한 기능 구현 (LookDev 포함)
- 렌더링 최적화 & Unreal Engine의 렌더링 기능에 대한 깊은 이해 (추후 다른 프로젝트를 통해 보충)
- MultiThread, Task 기반의 개발방법 (추후 다른 프로젝트를 통해 보충)

### 달성하지 못한 부분
- Save/Load기능 (UI는 배치되어있으나 기능은 개발되지 않음)
- LookDev
- 여러가지 효과 (레벨 전환 효과, UI의 이펙트)
- 총 약 5일정도의 추가 일정이 필요
    - 다음 프로젝트 진행 후 추가 개발 필요

## [4L](https://conceptboard.com/blog/4ls-retrospective-technique-free-template/)

### Like (잘 진행된 것은 무엇인가요?)
- 두근거림
    - 약 12년간의 직장생활에서 개발을 하는 것, 잘하는 것은 너무나도 당연한 일이었습니다.
    - 조금 돌아간다 생각하고 공부하기로 마음먹고 시작하고 2주간은 너무 힘들었습니다.
    - 상황과 환경, 내면의 소리로인해 조금 힘들었습니다.
    - 이 프로젝트를 시작하고, 내가 개발을 좋아한다는 것을 다시금 발견하게되었습니다.
    - 오래간만에 두근두근 행복한 개발의 순간들이었습니다.
- Unreal Engine으로 진행하는 구체적인 첫 프로젝트였습니다.
    - UE는 블루프린트만 조금 알던 상태에서 시작하여 약 3개월정도의 시간동안 작업했는데 생각보다 UE의 많은 부분을 훑어볼 수 있었습니다.
- S/W Flow 제어
    - 블루프린트로 작업되어있는걸 분석할 때 S/W의 흐름이 한눈에 파악되지는 않았습니다.
    - 분석된 내용을 일단 그대로 C++로 옮기다보니 조금 억지스러운 흐름들이 발생했습니다.
    - Manager 분리와 S/W 상태를 이용한 Flow 제어 작업을 추가하여 전체적인 흐름이 좀더 쉽게 파악될 수 있도록 작업했습니다.
    - 이런 작업방식은 흐름 제어를 일원화하여 개발자의 실수를 줄일 수 있습니다.
- Rx 스타일의 데이터 구독모델
    - 기존 로직은 데이터가 업데이트되면 UI를 직접 Update해줘야했습니다.
    - UI 갱신이 산발적으로 발생하다보니 UI제어에 대한 코드가 여기저기 흩뿌려져야했습니다.
    - 구독모델로 바꾸게되면 UI가 생성되면 해당 UI가 참조하는 Data에 Subscribe하게되고, Data가 업데이트되면 Callback을 통해 주입한 코드가 호출되어 UI의 처리를 Data와 분리할 수 있습니다.

### Learned (뚜렷하게 배운 점은 무엇인가요?)
- UE의 Feature들에 대해 조금은 깊게 들여다볼 수 있었습니다.
    - GamePlay Framework
    - GameInstance, GameMode, LevelScript, Actor등의 라이프사이클
    - UMG, CommonUI
    - Enhanced Input
    - Behavior Tree, EQS
    - Animation Mongate
    - Sound System
    - ETC
- 타 엔진들과 workflow가 조금은 다르지만 결국 비슷하다는 점을 알게되었습니다.
    - 초기에 손이 조금 많이들어가는 것 같습니다.
- Editor 확장, 기즈모 추가등에 대해서도 공부할 수 있었습니다. (코드 미포함)

### Lacking (무엇이 부족했나요?)
- 집에서 육아와 프로젝트를 동시에 진행하다보니 생각보다 느리게 진행되었습니다.
    - 마지막 3주정도는 아이가 아파서 거의 집중못했던 것 같습니다.
    - 회사에 소속되어있지 않다보니 이부분은 어쩔 수 없는 것 같습니다.
- 작업의 포커싱이 흔들리는경우가 많았습니다.
    - 직접 계획하고, 설계해서 작업하지 않은 프로젝트가 너무 오래간만입니다.
    - 작업하다보면 큰 그림단계에서 흔들려 길을 잃는경우가 많았습니다. (아무래도 직접 설계한게 아니다보니..)
    - 아무래도 블루프린트는 큰 구조를 이해하는 도구로는 부족함이 있어보입니다.
- 블루프린트에 대한 이해가 깊지않다보니 분석에 생각보다 시간이 소요되었습니다.
- 생각보다 UE C++프로젝트에 대한 레퍼런스가 부족했습니다.
    - 이 프로젝트가 조금은 이런 부분에 도움이 되었으면합니다.
- override가능한 함수들이 매우 많은데 이를 적극적으로 활용하지 못했습니다.
    - 각 클래스들에 대한 override가능한 함수들에 대한 공부가 필요할 것 같습니다.
- EQS와 Navigation의 처리가 매끄럽지 못했습니다. (아직 해당 부분에 대한 버그가 존재합니다.)
- 연출에 대한 작업을 후순위로 미뤄놓다보니 아직 작업되지못한부분이 있습니다.

### Long (이후 개선하고 싶은것은 무엇인가요?)
- 주변 환경과 상관없이 흐트러지지 않는 마인드셋을 위해 노력해야 될 것 같습니다.
- Save/Load처리 등 기본 기능들에 대한 처리가 우선되어야 합니다.
- 각 클래스들에 대한 override함수들에 대해 조금 더 확실한 이해가 필요할 것 같습니다.
- S/W Flow처리가 현재 단순히 함수들의 연결로 처리가되어있는데 Dependency, Async처리까지 진행하고싶습니다.
    - 멀티플레이 게임도 아니라서 조금 오버테크놀러지가 아닌가 싶긴한데 골이 그렇게 멀어보이진 않습니다.
- SimpleRX를 조금 더 개발해보고싶습니다.
    - Thread 전환, 조건제어, Timer를 이용하지 않은 Tick 등
- 기존 Sample프로젝트와 색감차이가 좀 나는 것 같습니다. UE에서의 LookDev에 대해서도 추가적인 공부/작업이 필요합니다.
